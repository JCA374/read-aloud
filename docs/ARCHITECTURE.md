# How Neural Voices works

A Manifest V3 add-on for Firefox and Chromium. Everything runs inside the browser: Piper voices as
WebAssembly, no server. There's no build step: `extension/` is loaded as it is, and `./build.sh` only zips it.

## Files

| File | Runs in | What it does |
|---|---|---|
| `manifest.json` | | One manifest for both browsers. Firefox uses `background.scripts`, Chromium uses `background.service_worker` (each ignores the other). |
| `common.js` | everywhere | `NV`: default settings, choosing the voice for a language (`voiceFor`, `pick`), `sendToTab`, PDF helpers. |
| `catalog.js` | background, worker, settings | `NV_CATALOG`: the 170 voices, generated by `tools/make-catalog.mjs`. Don't edit by hand. |
| `content.js`, `content.css` | every page | Finds the text, splits it into sentences, asks for speech, plays it, highlights sentence and word, and shows the player and the selection speaker (in a closed shadow root). |
| `background.js` | background page (Firefox) / service worker (Chromium) | Routes messages: speech requests to the engine, menu items and shortcuts to the tab, and one tab reading at a time. |
| `engine/host.js` | background page (Firefox) / `offscreen.html` (Chromium) | Starts the worker, keeps the last 30 results, and stops the worker after 5 idle minutes. |
| `engine/piper-worker.js` | Web Worker | Downloads and caches voices, espeak-ng phonemes → ONNX Runtime → WAV with estimated word times. |
| `engine/vendor/` | Web Worker | ONNX Runtime Web 1.30.0 and piper-wasm 1.0.0, unchanged from npm (see its README). |
| `offscreen.html`, `offscreen.js` | Chromium only | A hidden page that hosts the worker, because a service worker can't start workers. Left out of the Firefox build. |
| `popup.*` | toolbar popup | Read page, click-to-read, voice, speed, Settings, *Read this PDF*. Warms up the voice when it opens. |
| `options.*` | Settings tab | Voice list and catalogue, language defaults, reading options, storage, reset/export/import. |
| `pdf.html`, `pdf-viewer.js`, `pdf.css`, `pdf/` | add-on tab | The PDF viewer (pdf.js 6.4.299). Draws the pages and puts an invisible text layer over them, grouped into paragraphs (`data-nv-block`), which `content.js` reads like a web page. |

## The way a sentence becomes sound

```
content.js ──{type:"tts", voice, text, speed, say?}──▶ background.js ──▶ engine/host.js ──▶ piper-worker.js
     ▲                                             (Firefox: direct call;          espeak-ng → ids
     │                                              Chromium: via offscreen.html)  ONNX Runtime → audio
     └──────────── {audio: base64 WAV, words: [[text, start, end]], duration} ◀───────────────┘
```

- **Pieces.** Where reading starts, the text is cut into growing pieces of at most 45, 80, 140, then 220
  characters (`STAGES` in `content.js`), so the first sound comes quickly and each piece renders while the
  one before plays. After that it keeps about 60 s of audio ready (`AHEAD_SECONDS`, at most 30 pieces).
- **Your pronunciations.** `ttsRequest` in `content.js` applies `NV.applyDictionary` (in `common.js`) with
  the voice's language and adds the result as `say` when it differs. The worker phonemizes `say` but
  estimates word times from `text`, so the highlight keeps the page's words. Pieces are keyed with a
  dictionary revision, so a change re-renders what isn't playing yet. espeak-ng in piper-wasm doesn't take
  phonemes as input, so entries are respellings, not IPA.
- **Language.** Each paragraph with 8 or more words gets a language from the browser's built-in detector
  (`chrome.i18n.detectLanguage`, offline, any language; `detectLang`). When it isn't sure, English and
  Swedish are told apart by common words, and otherwise the page's `lang` attribute is used. Shorter
  paragraphs keep the language before them. The voice shown before reading (player, popup) uses the page's
  main text the same way (`pageGuess`). `NV.voiceFor` then picks a voice from your list.
- **Speed** is set in the model (Piper's length scale), so the pitch stays natural. The model shortens pauses
  less than sounds, so `lengthFor(speed)` in `piper-worker.js` follows a measured curve to make 2× really
  about 2× (measured with `tests/engine/speed-calibration.py`).
- **Word times** are estimated (`estimateWords`): words are spread over the audio by length, with pauses at
  punctuation (Piper doesn't report them), so the word highlight can run
  a little ahead or behind.
- **Memory.** At most two voices stay loaded (`KEEP_VOICES`), never the one that's speaking. After 5 idle
  minutes the worker stops (Chromium also closes the offscreen page).

## Messages

To the background (`chrome.runtime.sendMessage`, field `type`):
`tts`, `voices` (the list without download details), `download`, `unload`, `warm`, `reading` (a tab's
state, for "one tab at a time"), `openPdf`, `openOptions`, `keepAlive` (sent every 5 s while a `tts` request
waits: Firefox closes a background page after 30 s without events, even mid-render). Internal:
`voiceProgress`, `engineIdle`, and messages with `target: "offscreen"` (Chromium).

To a tab (`NV.sendToTab`, field `cmd`): `readSelection`, `readFromHere`, `readPage`, `toggle`, `stop`,
`clickMode`, `voiceProgress`, `status`. Every command except `voiceProgress` replies with the tab's state.
The PDF viewer is an add-on page, which `tabs.sendMessage` can't reach, so `sendToTab` falls back to a
runtime message with `toTab: <tab id>`.

## Storage

| Where | What |
|---|---|
| `chrome.storage.local` | Settings: the keys of `NV.DEFAULTS` in `common.js` (`voice`, `voiceSv`, `langVoices`, `autoDetect`, `fixedVoice`, `shown`, `speed`, `volume`, `highlight`, `autoScroll`, `pause`, `skipCode`, and `dictionary`: `[{word, say, lang}]`, `lang` "" for every voice). |
| `chrome.storage.session` | `readingTab`: the tab that's reading (the background can be unloaded between events). |
| Cache API, cache `piper-voices` | Voice files (`.onnx`, `.onnx.json`), keyed by their pinned URL. Settings shows the size and deletes them. |

## Voices and the catalogue

- Voices download from [rhasspy/piper-voices](https://huggingface.co/rhasspy/piper-voices), **pinned to one
  revision**, so the files can't change. Each download is checked against the expected size, tried 3 times,
  and a voice that fails to load is deleted so it downloads again.
- `node tools/make-catalog.mjs` rebuilds `catalog.js` from the newest revision. It leaves out voices the
  bundled espeak-ng can't handle (Chinese, Japanese, Thai, Hebrew, Lithuanian, one Ukrainian). It turns each
  model card's licence into a short name and a kind (free, share-alike, non-commercial, none), and prints
  the counts. The five starter voices must stay free to use; `tests/run.sh` checks this.
- A voice downloaded at an older revision is kept (if its size matches) when the catalogue moves on.

## PDFs

The browsers' own PDF viewers don't run add-on scripts, so PDFs open in `pdf.html?file=<url>[&read=1]`:
- Chromium: *Read page* on a PDF runs in the viewer's outer page and hands over.
- Firefox: the popup shows *Read this PDF*. Shortcuts and *Read aloud from here* fall back to opening the viewer.
- Everywhere: right-click a PDF link → *Read PDF aloud*, or open or drop a local file in the viewer.
- Fetching a PDF from a site uses the optional host permission for that site, asked for the first time.
- pdf.js runs without PDF scripts or XFA forms, with `isEvalSupported: false`.

## Firefox and Chromium differences

| | Firefox | Chromium |
|---|---|---|
| Background | event page (`background.scripts`) | service worker |
| Engine host | the background page itself | `offscreen.html` |
| Idle background | closed after 30 s without events, even mid-render: `content.js` sends `keepAlive` while it waits | — |
| Build | `dist/firefox/` without the offscreen page, its permission and the service worker entry | the full `extension/` |
| PDF in the browser's viewer | popup → *Read this PDF* | *Read page* hands over by itself |

## Tests and tools

- `tests/run.sh`: instant checks plus browser tests in headless Chromium and Firefox. See `tests/README.md`;
  results are in `tests/RESULTS.md`.
- `tools/check-vendor.sh`: checks the 204 bundled library files against npm.
- `tools/sign.sh` and `tools/amo.py`: signing and Mozilla's API (see `RELEASING.md`).
- `tools/make-icons.py`: draws the add-on icon (`extension/icons/`); needs Pillow.

## Decided against (don't build these again)

- **Reading pages in Firefox's add-on store (addons.mozilla.org).** Firefox runs no add-on scripts there and
  refuses add-ons' requests for its pages; this blocks every read-aloud add-on, not just this one. A reader
  tab that got an add-on's text from the store's public API was built and tested on 2026-11-08, then removed
  (commit 20f92f4 reverts 88d326e): little use, and it cost three files, a test, and one more address in the
  privacy policy and reviewer notes. The popup only says why such a page can't be read.
